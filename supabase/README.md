Supabase RLS + is-admin Edge Function — Quick README

This README contains exact SQL to run in the Supabase SQL editor, a short deployment guide for an Edge Function that checks admin status server-side, and a safe test curl command.

IMPORTANT WARNINGS (READ FIRST)
- NEVER run `SELECT`, `INSERT`, `UPDATE`, or `DELETE` on sensitive tables (like `admin_emails`) from client-side/browser code. Always call a server-side function or Edge Function that uses the Supabase service_role key.
- NEVER commit your Supabase service_role key to source control or expose it to the browser.
- Apply RLS (row-level security) statements only via Supabase SQL editor or a protected CI pipeline with the service_role key.

1) Exact SQL statements to run in Supabase SQL editor

-- Create table (run once)
CREATE TABLE IF NOT EXISTS public.voice_profiles (
  id uuid GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  tone text NOT NULL DEFAULT 'professional',
  confidence_level int NOT NULL DEFAULT 65,
  emotional_depth int NOT NULL DEFAULT 50,
  sentence_length text NOT NULL DEFAULT 'medium',
  preferred_words text[] DEFAULT array[]::text[],
  avoided_words text[] DEFAULT array[]::text[],
  example_responses text DEFAULT '',
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_voice_profiles_user_id ON public.voice_profiles(user_id);

-- Enable RLS and owner-only policies for voice_profiles
ALTER TABLE IF EXISTS public.voice_profiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY voice_profiles_insert_owner ON public.voice_profiles
  FOR INSERT
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY voice_profiles_manage_owner ON public.voice_profiles
  FOR ALL
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);

-- Harden admin_emails: disable public selects
ALTER TABLE IF EXISTS public.admin_emails ENABLE ROW LEVEL SECURITY;

CREATE POLICY admin_emails_no_public_read ON public.admin_emails
  FOR SELECT
  USING (false);

// see src/api/isAdminEdgeServerExample.js in this repo for the complete example

Key steps to deploy on Supabase (recommended):
- Install supabase CLI: https://supabase.com/docs/guides/cli
- Run: `supabase login` and authenticate
- From your functions directory, create a new function (JavaScript/TypeScript) with the code in `src/api/isAdminEdgeServerExample.js`.
- Set environment variables for the function (in Supabase dashboard -> Settings -> Environment variables):
  - SUPABASE_URL = https://your-project-ref.supabase.co
  - SUPABASE_SERVICE_ROLE_KEY = <your-service-role-key>  (DO NOT commit this)
- Deploy the function with `supabase functions deploy is-admin` (replace with your function name)

3) Example curl to test (replace <EDGE_URL> and host values):

curl -X POST "https://<REGION>-<PROJECT_REF>.functions.supabase.co/is-admin" \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com"}'

Expected response: { "isAdmin": true } or { "isAdmin": false }

4) Client-side usage (after deploy)
- Client code should call the Edge Function (not Supabase) to check admin status. Example:

fetch('/.netlify/functions/is-admin', { method: 'POST', body: JSON.stringify({ email }) })
  .then(r => r.json())
  .then(data => data.isAdmin && doAdminStuff());

5) RLS testing checklist
- Before enabling RLS, ensure server-side code (Edge Function) is working with service_role key.
- After enabling RLS, test with a normal user session (should only be able to access their own voice_profile row).
- Test Edge Function with curl (service_role) to confirm admin detection works.

6) Troubleshooting & notes
- If you lock yourself out after enabling RLS, use the Supabase SQL editor (project owner) to revert policies.
- Keep the service_role key rotated periodically and stored securely (Vault / Secrets manager).
